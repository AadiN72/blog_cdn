Before I start my journey into robotics, I thought it would be fun to explain how I made this blog and how it actually works.

## Tech stack

So, first: the million-dollar question. The tech stack:

- The frontend was made with React
- The database is Firebase Firestore
- The assets are hosted through GitHub
- There is no editor yet (just VS Code). I may use Plate.js later.

# How do I make websites?

Since I'm generally trying to focus much more on electronics, robotics, and hardware, I don't actually do that much web development. I learnt web development because it's a useful skill, but I don't want it to be my main focus.

As such, nearly all of my sites are made by Copilot, with my amazing oversight.

This site was completely built by Copilot, with plenty of minor suggestions and an overall design and architecture from me.

The humble beginnings were heavily inspired by the blog of [heftymouse](https://heftymouse.me/). Sorry, but I loved the style. I retained the really fun 👋 emoji and the overall feel of the site because, well, we all have to start somewhere.

Armed with various images, ideas, and the GitHub code of the site, I started putting together the bones of this blog.

# CDN

CDN stands for Content Delivery Network. Basically, it's a system for delivering assets such as images and other files over the internet.

As a broke college student, I really didn't have that many options:

- Cloudflare — needed a card to activate it, and I had no history
- Contentful — way too large for what I needed
- GitHub — good enough
- Firebase Storage — more than I wanted to pay for
- Supabase Storage — I didn't want to rely on a project that could shut down due to inactivity (definitely 😭)

I ended up making the GitHub repository [blog_cdn](https://github.com/AadiN72/blog_cdn). I then used [Octokit's request library](https://github.com/octokit/request.js/) to fetch the data.

In the repository, I made some scripts to upload the images first and then hydrate them with the URLs pointing to the files on GitHub.

GitHub is a decent asset host for my purposes. It's certainly not what you'd normally reach for when building a serious production CDN, but for a small personal blog with very little traffic, it works perfectly well.

And let's be honest: if this blog ever gets enough traffic to make me worry about GitHub's limits, I'll probably be celebrating.
