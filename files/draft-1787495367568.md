# The beginning

Finally, the odyssey begins.

This is Week 1 of what is hopefully going to be a very long journey into embedded systems, control, and eventually robotics.

This week, I learned C++.

C++ is especially important for where I want to go because it shows up constantly in embedded systems and robotics. Boards like Arduino and ESP32 are commonly programmed using C/C++, and later on I'll probably encounter it again when working with things like ROS, real-time systems, and robot control.

But before talking about C++, I first want to talk about how I learn programming languages.

## How I learn languages

I tend to learn programming languages through the **quirks they possess**.

When I'm writing code, I usually don't think directly in Python, C, or C++. I think in blocks of logic or pseudocode first, and then translate that logic into whatever language I'm using.

For example, let's say I want to add two numbers.

The logic is simply:

```text
get number a
get number b
c = a + b
print c
```

In Python, that becomes:

```python
a = int(input("Enter a: "))
b = int(input("Enter b: "))

c = a + b

print(c)
```

In C:

```c
#include <stdio.h>

int main() {
    int a, b, c;

    printf("Enter a: ");
    scanf("%d", &a);

    printf("Enter b: ");
    scanf("%d", &b);

    c = a + b;

    printf("%d\n", c);

    return 0;
}
```

And finally, in C++:

```cpp
#include <iostream>
using namespace std;

int main() {
    int a, b, c;

    cout << "Enter a: ";
    cin >> a;

    cout << "Enter b: ";
    cin >> b;

    c = a + b;

    cout << c << '\n';

    return 0;
}
```

All three programs do exactly the same thing.

The interesting part is how differently each language wants me to express the same logic.

Python doesn't need a `main()` function, variables don't need their types declared beforehand, and `input()` always gives us a string unless we convert it.

C is much more explicit.

We need a `main()` function, variables have declared types, and functions like `scanf()` use formatting like `%d` to specify what type of input we're expecting.

C++ keeps some of that structure from C, but changes the way we interact with things like input and output.

## The quirks of C++

So far, these are the main quirks I've noticed.

### `main()`

Like C, execution starts from:

```cpp
int main() {

}
```

Coming from Python, needing an actual entry point for the program feels slightly strange at first.

### Headers

Even basic things like input and output require us to include a header:

```cpp
#include <iostream>
```

This gives us access to things like `cin` and `cout`.

### Namespaces

Then there's this:

```cpp
using namespace std;
```

At first it looks like random C++ magic, but it's actually pretty simple.

Things like `cout` and `cin` belong to the `std` namespace.

Without `using namespace std;`, I would have to write:

```cpp
std::cout << "Hello\n";
std::cin >> a;
```

A namespace is basically a way of grouping names together.

For example, I could make my own:

```cpp
namespace aadi {
    int value = 10;
}
```

and then access it using:

```cpp
aadi::value
```

So:

```cpp
std::cout
```

basically means:

> use `cout` from the `std` namespace.

Using:

```cpp
using namespace std;
```

just means I don't have to type `std::` every single time.

### `cin`

Input in C++ is done using:

```cpp
cin >> a;
```

One thing I like about this is that it works with the type of the variable.

If I declare:

```cpp
int a;
```

then:

```cpp
cin >> a;
```

tries to read an integer into `a`.

Compare that to Python, where:

```python
a = input()
```

always starts as a string and has to be converted manually.

### `cout`

Output uses:

```cpp
cout << "Hello";
```

The `<<` syntax is probably one of my favourite things about C++ so far.

You can chain different values together very easily:

```cpp
int age = 18;

cout << "Age: " << age << '\n';
```

There's no need to manually convert `age` into a string, and unlike C, I don't need to think about format specifiers like `%d`.

It feels very natural once you get used to looking at it.

## What is always the same?

The biggest thing I've realised is that while syntax changes, **programming logic usually doesn't**.

An `if` statement is still an `if` statement.

A loop is still a loop.

A switch is still a switch.

Functions are still functions.

And when working with object-oriented languages, concepts like classes and enums generally follow the same underlying ideas even if the exact syntax changes.

For example:

```text
if score > 50
    print pass
else
    print fail
```

That idea can be translated into basically any programming language.

So learning another language isn't really relearning programming from zero.

It's more like learning how that language wants you to express ideas you already understand.

And that's why I like learning languages through their quirks.

Once I understand those quirks, everything else starts falling into place.
